Privacy Policy

Last Updated: June 29, 2026 · v5.4.3

GlassChat is built to minimize plaintext exposure. We collect the information needed to run accounts, messages, media, calls, safety controls, and push delivery while encrypting private content before it leaves user devices.

Information We Collect

  • Account data: email address, username, display name, Firebase user ID, and authentication state.
  • Profile data: avatar, profile bio, phone number if provided, privacy settings, blocked users, active sessions, and device preferences.
  • Communication data: encrypted messages, encrypted media files, encrypted call signaling data, call logs, delivery status, read receipts, typing state, and presence signals.
  • Device data: push notification device tokens, session identifiers, app version, and local settings needed for notifications and account security.

Encryption Details

Message content is protected with AES-256-GCM using 256-bit keys.

Conversation keys are established with X25519 ECDH, which provides a 256-bit security level, and derived with HKDF-SHA256.

Local cache data is protected by SQLCipher with AES-256-CBC. Private keys, credentials, and sensitive tokens are stored with EncryptedSharedPreferences backed by Android Keystore.

Sender Device

Plaintext is encrypted locally with AES-256-GCM before upload.

Firebase / Supabase

Servers store and route ciphertext only. They cannot decrypt without endpoint keys.

Receiver Device

Ciphertext is delivered and decrypted locally on the receiver's device.

What's Encrypted

Message content and replies are encrypted with the conversation key before upload.

Media files, including images, videos, voice notes, and documents, are encrypted with per-media file keys.

Call signaling data, profile bio, phone number, push notification previews, conversation last messages, local credentials, local message cache, and call logs are encrypted or stripped so services cannot read private content.

Key Storage

Private keys and sensitive credentials are stored in EncryptedSharedPreferences backed by Android Keystore.

Android Keystore backing helps keep key material isolated from normal app storage. If an account is deleted, locally stored encryption keys are deleted with that account state.

Zero-Knowledge Architecture

GlassChat server operators cannot decrypt user messages or media because decryption keys remain on endpoint devices.

Firebase, Supabase, and notification infrastructure process ciphertext, routing data, or generic delivery metadata. They do not receive the keys required to turn ciphertext back into plaintext.

Third-Party Services

  • Firebase Authentication: user identity management. Data access: email, username, user ID.
  • Firebase Firestore: encrypted message storage and call signaling. Data access: encrypted message content only.
  • Supabase Storage: encrypted media file storage. Data access: encrypted files only.
  • OneSignal: push notifications. Data access: device tokens and generic notification payloads.
  • Stream WebRTC: peer-to-peer call facilitation. Data access: encrypted SDP offers, answers, and ICE candidates.

What Third Parties See

Firebase Authentication sees account identity data such as email, username, and user ID.

Firebase Firestore stores encrypted message content and encrypted call signaling; it cannot decrypt user content.

Supabase Storage receives encrypted media files only and cannot decrypt them.

OneSignal receives device tokens and generic "New message" notifications with encrypted preview data in the payload.

Stream WebRTC sees encrypted SDP offers, answers, and ICE candidates. No third-party service receives the keys needed to decrypt private content.

Local Storage

GlassChat uses SQLCipher with AES-256-CBC for the local database and EncryptedSharedPreferences backed by Android Keystore for credentials, tokens, and private key material.

Users can clear local message cache from Settings. Clearing local cache removes local copies and allows server-backed encrypted records to resync where available.

User Rights

  • Access stored account data and review profile, privacy, and active-session settings.
  • Export conversation history where the app provides export controls.
  • Request account deletion and data deletion by contacting support.
  • Clear local message cache from Settings and revoke active sessions from Settings.
  • Block other users to prevent contact.
  • Have local encryption keys deleted with account deletion state.
  • Have deleted messages removed from Firestore according to the deletion request and available retention controls.
  • Encrypted media files remain in Supabase Storage until manually deleted or after 90 days of inactivity.
